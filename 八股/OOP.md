# 面向对象 OOP 面试八股（速答版）

> 目标：把“概念”讲成“设计动机 + 代码落点 + 取舍”，并能接住追问。

---

## 1) 三大特性：封装 / 继承 / 多态

### 一句话回答
OOP 的核心是用“对象”承载状态与行为，并通过 **封装** 隐藏实现细节、通过 **继承/组合** 复用与扩展、通过 **多态** 用统一接口屏蔽具体类型差异，从而降低耦合、提升可维护性。

### 1.1 封装（Encapsulation）
- **定义**：把数据与操作数据的方法绑定在一起，对外暴露稳定接口，隐藏内部实现。
- **价值**：
  - 限制不变量被破坏（例如余额不能为负）。
  - 降低调用方对内部结构的依赖（可替换实现而不改调用方）。
- **落地**：访问控制（private/protected/public）、只读属性、setter 校验、不可变对象。

### 1.2 继承（Inheritance）
- **定义**：子类复用父类行为并可扩展/覆写。
- **价值**：代码复用、抽象共性。
- **风险**：继承会引入强耦合与脆弱基类（base class fragile problem），更推荐“组合优于继承”。

### 1.3 多态（Polymorphism）
- **定义**：同一个接口/父类型引用，在运行时可指向不同子类型对象，表现出不同实现。
- **价值**：调用方只依赖抽象（接口/父类），新增子类不改调用方（符合开闭原则）。

## 2) 多态：重写（Override） vs 重载（Overload）

### 一句话回答
- **重写/覆写（override）**：子类用相同方法签名替换父类实现，属于**运行时多态**。
- **重载（overload）**：同一作用域内方法名相同、参数列表不同，由编译器选择，属于**编译期多态**。

### Java 示例（最常见面试语境）
```java
class Animal {
    public void speak() { System.out.println("..."); }
}

class Dog extends Animal {
    @Override
    public void speak() { System.out.println("wang"); }

    // overload：同名不同参
    public void speak(int times) {
        for (int i = 0; i < times; i++) speak();
    }
}

Animal a = new Dog();
a.speak();          // override：运行时决定调用 Dog.speak
new Dog().speak(3); // overload：编译期决定调用 speak(int)
```

### 易错点（很常考）
- **重写**要满足：方法名+参数列表一致，返回类型协变可行（语言相关），访问权限不能更严格。
- **重载**只看“参数列表”是否不同：参数个数/类型/顺序不同。

### Python 怎么回答更准确（如果面试官切 Python）
- Python 没有“编译期重载”，同名方法后定义会覆盖前定义。
- 常见替代：默认参数、`*args/**kwargs`、`functools.singledispatch`。

```python
from functools import singledispatch

@singledispatch
def area(x):
    raise TypeError

@area.register
def _(x: int):
    return x * x

@area.register
def _(x: tuple):
    w, h = x
    return w * h
```

## 3) 接口多实现、抽象类单继承

### 一句话回答
- **接口（Interface）**用来定义“能力/契约”，类可以**实现多个接口**来组合能力。
- **抽象类（Abstract Class）**通常承载“共享状态 + 部分实现 + 模板方法”，大多数语言中类对抽象类是**单继承**，以避免菱形继承等复杂性。

### 什么时候用接口？什么时候用抽象类？
- 用接口：
  - 只需要约束行为，不需要共享字段。
  - 希望一个类具备多种能力（多实现）。
- 用抽象类：
  - 有共享代码/公共字段/统一生命周期。
  - 需要提供默认实现，减少子类重复。

### 常见追问：为什么很多语言类是单继承？
- 主要是避免多继承带来的方法/字段冲突（菱形问题），降低复杂度；通过“接口 + 组合”替代多继承。

## 4) SOLID 五大原则（面试可直接背）

### 一句话总览
SOLID 目标是：让系统**更易扩展、更易测试、更少改动影响面**。

### S — 单一职责（SRP）
- 一个类/模块只对一种变化原因负责。
- 口诀：改需求时，尽量只改一个地方。

### O — 开闭原则（OCP）
- 对扩展开放，对修改关闭。
- 落地：面向接口编程 + 多态；新增实现类而不是改旧逻辑分支。

### L — 里氏替换（LSP）
- 子类必须能替换父类而不破坏正确性。
- 常见踩坑：子类强化前置条件、削弱后置条件、抛出不兼容异常。

### I — 接口隔离（ISP）
- 不要强迫客户端依赖它不需要的方法。
- 落地：拆小接口（能力接口），避免“上帝接口”。

### D — 依赖倒置（DIP）
- 高层模块不依赖低层模块，都依赖抽象；抽象不依赖细节，细节依赖抽象。
- 落地：依赖注入（构造器注入/接口注入）、面向接口。

## 5) 常考补充（建议你也能顺口讲）

### 5.1 组合优于继承
- 继承表达“is-a”，组合表达“has-a”。
- 组合更灵活：运行时替换组件，避免继承层级爆炸。

### 5.2 静态绑定 vs 动态绑定
- 静态绑定：编译期决定调用（典型：重载）。
- 动态绑定：运行时根据真实对象类型决定调用（典型：重写 + 虚方法表）。

### 5.3 设计模式与 OOP 的关系（答法）
- 设计模式是 SOLID 的实践套路：
  - 策略模式：用组合实现 OCP（替换算法）。
  - 工厂模式：把创建与使用解耦（DIP）。
  - 模板方法：抽象类里固化流程、子类填空。

### 5.4 面向对象的“抽象”怎么讲
- 抽象是抓住本质、隐藏细节：对外暴露“意图”而不是“实现”。
